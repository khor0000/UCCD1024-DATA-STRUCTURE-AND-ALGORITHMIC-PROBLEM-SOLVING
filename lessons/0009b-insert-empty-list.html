insert: the empty list case

insert handles three different situations, because "put a new box at position at" means something different depending on what's already there. This lesson is the simplest of the three: the list has nothing in it yet.

bool List::insert(int at, int newItem) {
    Node *pre, *cur, *tmp = new Node(newItem);

    if (at < 1 || at > count+1) return false;  // legal range — Lesson 9
    if (!tmp) return false;                     // did "new" actually succeed?

    if (empty()) {                              // ← this lesson
        head = tmp;
        count++;
        return true;
    }
    // every other case — next lessons
}
Three new things showed up in that block at once — none of them are today's topic, so here's each in one line before moving on:
New thingWhat it means
Node *pre, *cur, *tmp = new Node(...);Three separate pointer declarations, squeezed onto one line — each name needs its own *, and only tmp gets a starting value right now. It's exactly the same as writing three lines: Node *pre; Node *cur; Node *tmp = new Node(...);. pre and cur exist as empty boxes, reserved for the next two lessons — ignore them entirely today.
if (!tmp)A pointer can be tested directly in an if: non-NULL counts as true, NULL counts as false. So !tmp means "tmp is NULL" — i.e. "the new above failed to get memory." This almost never actually happens on this course; it's defensive code. Skim it and move on.
empty()A member function of List (like find), called with no arguments. Its entire body, in full:
 
bool List::empty() {
    return count == 0;
}

That's it — one line. It reads count (the same field you already know from Lesson 7) and hands back true or false depending on whether it's zero. if (empty()) in the code above is exactly the same question as writing if (count == 0) directly — empty() is just a shorter, more readable name for that one check.

The only line that's actually today's lesson is inside the if (empty()) block. Everything above it is context to make the function read correctly; none of it needs to be memorised today.

There's no chain yet

If head is NULL, there is no existing chain yet. There is nothing for the new node to attach to. So its next stays exactly as it was — already NULL, set back in Lesson 6f's constructor, before insert ever ran. The new node doesn't join a list. It simply becomes the whole list:

5NULL
head (was NULL, now points here)

head = tmp; copies tmp's address into head — nothing more. head is the only way anything ever reaches the list, so once it points at nothing but this one node, walking from head can only ever find this one node. That's what "the new node becomes the whole list" actually means — it's the consequence of that one copy, not a separate thing that happens. Then count++; brings the count from 0 to 1, and the function returns true.

This case only ever touches one variable: head. That's what makes it the simplest of the three.
Critical Exam Trap • The Semicolon On count++

++ is an operator, not a statement terminator. count++ is a complete expression but not a complete statement until a ; closes it — exactly like x = 5 needs its ;. It reads as finished because ++ looks like punctuation; it isn't.
