Pointers to structs

Lesson 1: a pointer holds an address. Lesson 2: a struct is a bundle of fields you reach with a dot. Now combine them — instead of a pointer to an int, make a pointer to a whole card.

Back to the ID card. Say Alex's card is sitting in a filing cabinet drawer. Instead of carrying the whole card around, someone hands you a sticky note: "Alex's card is in drawer 104." That sticky note is a pointer to the struct — not the card itself, just where to find it.

struct Student { string name; int mark; };

Student a;
a.name = "Alex";
a.mark = 88;

Student *sp = &a;   // sp holds the address of a — the sticky note

cout << sp->name;    // Alex
cout << sp->mark;    // 88

sp->name means "follow sp to the card it points at, then read the Name field." It's doing two things in one symbol: dereference (follow the pointer) and access a field. You could write it the long way and get the exact same answer:

cout << (*sp).name;   // identical to sp->name — just uglier

Dot vs. arrow

You're holdingTo read a field
Dotthe struct itselfa.mark
Arrowa pointer to the structsp->mark (short for (*sp).mark)
This is the single most useful rule for reading List/Node code fast: look at the variable's declared type. If it says Node, it's a dot. If it says Node *, it's an arrow. The code never mixes them up — if you see a dot where you expected an arrow, that's either a bug or you misread the type.

Quick check — Student *sp = &a;. Which reads a's mark through sp?

Right — sp is a pointer to the struct, so it's the arrow.
sp's declared type is Student * — a pointer — so dot alone doesn't work here; it needs the arrow (or the clunkier (*sp).mark).

Second check — write the long-hand equivalent of sp->mark, using * and a dot.

Exactly — dereference first, then dot into the result.
Start from "follow sp" (that's *sp), wrap it in parentheses, then dot in for the field.

Once dot-vs-arrow feels automatic, you have everything needed to understand a Node. Ask now if it doesn't yet.
