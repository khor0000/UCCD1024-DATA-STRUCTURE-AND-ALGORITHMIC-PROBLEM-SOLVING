Lesson 15 of the linked-list crash sequence · Theory (midterm Q3b)

Deep copy vs shallow copy

A shallow copy copies the List's own variables (head, count) but not the Nodes they point to — both Lists end up sharing one chain. A deep copy makes brand-new Nodes too, so each List has its own separate chain.

Think of head as a locker number written on a sticky note, not the locker itself. Copying the sticky note (shallow copy) gives you a second note with the same number on it — both notes point at the one shared locker. Making a deep copy means renting a brand-new locker, moving the contents in, and writing the new locker's number on your note instead.

The setup: copying a List

Say you have List a; already holding the chain 10 → 20, and you write:

List b = a;

The same rule you just learnt, applied to List

From lesson 15a: = on a struct copies every field, one by one. List has two fields, so List b = a; quietly does the same job as writing both of these yourself — exactly as book b = a; copied a title and a page count:

b.head = a.head;
b.count = a.count;

That's it — nothing about the Nodes head points at is touched. Only the field values — the addresses and numbers stored directly inside the List struct — get copied. This is a shallow copy, and it's what C++ does automatically for List b = a; unless you write extra code to do something else.

Two different addresses live in one line — only one of them matters

Before any diagram, settle this, because everything below depends on it. Look at a single field:

head = 0x500

There are two addresses hiding in that line, and they are not the same thing:

ExampleMatters for Q3b?
The address where head lives0x900No. Never. It is bookkeeping.
The address head holds0x500Yes. This is the entire answer.

Whenever this lesson says "the same address" or "a different address", it means the second one — the value written inside head. It never means where the field itself sits.

You might reasonably wonder: does a deep copy move the List’s fields to different addresses, or split them apart somehow? No. In both kinds of copy, b is one struct with two fields sitting in one contiguous block of memory, exactly like a. Fields of a single struct are always adjacent and cannot drift apart. That part of the picture is identical in a shallow copy and a deep copy, and it is never what the question is about.

A struct spans several addresses only in the trivial sense that its fields have different sizes and therefore different offsets inside that one block — count at 0x8FC, head four bytes later at 0x900. Do not read exact byte sizes off these diagrams; the numbers are chosen to be legible, not to be arithmetically accurate, and no question here asks for them.

So what is the difference?

A deep copy creates new Nodes. A shallow copy does not. That is the substance of the whole topic, in one sentence.

b.head ending up with a different value is not a separate fact to memorise — it is the visible symptom of that one difference. New nodes exist, so b.head holds the address of one of them.

How you are allowed to draw it

Either form from lesson 7 is accepted here — one box labelled List with both fields named inside it, or two separate one-cell boxes. Splitting the box is a drawing choice, not part of the answer.

There is exactly one constraint. head’s value must be written down and legible, and the arrow must leave head specifically — never count, which is a plain number and points at nothing. A drawing that reads head = 0x500 inside a single labelled box satisfies that completely.

Critical Exam Trap • Every Arrow Leaves The Pointer

An arrow always runs from the box that holds the address, to the box living at that address. Never the reverse. Both a.head and b.head hold 0x500, so both arrows leave them and converge on box1 — box1 holds neither of their addresses and has no arrow back to either.

Correct (earns marks)Incorrect (loses marks)
a.head → box1 ← b.head — two arrows converging a.head → box1 → b.head — a chain through b.head

a.head and b.head are two separate boxes — but they hold the same address, 0x500. Both arrows point at the one box1. There is still only one chain in memory. Now suppose something later deletes a’s first node — the memory at 0x500 is handed back and that box stops existing. (You will write the operation that does this on Day 4; you do not need it here.) a.head gets updated to point at box2, but nothing tells b: b.head is left still holding 0x500, the address of a Node that no longer exists. Reading through b after that is reading through a dangling pointer.

Which way do the arrows go? Every arrow in these chains points forward only — head to box1, box1 to box2, and box2 to nothing. There is never a backward arrow, and this is not a drawing convention: box1’s next cell physically holds box2’s address, while box2 holds only an item and NULL. Box2 stores no address at all, so it has no way to refer back to box1 and there is nothing for a backward arrow to represent.

That is what singly linked means. From box2 you can never get back to box1. (A doubly linked list adds a second pointer field for exactly this purpose — it is not in your syllabus.)

What a deep copy does instead

A deep copy doesn't just copy head's value — it walks a's chain and calls new Node(...) for each item, building b a completely separate chain with the same items in the same order. After a deep copy, b.head holds a different address (0x560, a freshly-newed box1-copy) — not 0x500 — and that new box's next points at another freshly-newed box (0x580), not at a's 0x520:

You might reasonably wonder: does a deep copy create a whole new List? No. b already exists — it came into being the moment you wrote List b, and its count and head boxes sit at the same addresses whichever kind of copy happens. Nothing about copying moves b.

What a deep copy builds is a second chain of Nodes, and that is the only difference between the two operations. Both copy count. Both write an address into b’s own existing head box. Only the deep one first calls new for each item, so the address it ends up writing is a different one.

In one line: shallow and deep differ in exactly one thing — whether new Nodes are created.

Both Lists still carry count = 2 — a deep copy copies the plain fields too, exactly as a shallow copy does. The only difference between the two pictures is the value inside b.head: 0x500 (a’s node) versus 0x560 (b’s own node). Now a and b have two fully independent chains (0x500/0x520 vs. 0x560/0x580) that happen to hold equal values. Removing from a never affects b, because they don't share a single Node address.

Exam-ready answer (Q3b, theory): "A shallow copy copies only the head pointer and count, so both Lists end up pointing at the same chain of Nodes. A deep copy creates new Nodes for the second List, so the two Lists have separate chains that don't affect each other."

List a holds 10 → 20. You run List b = a; (a shallow copy), then a’s first node is deleted. What does b look like now?

Right. A shallow copy never gave b its own Nodes — b.head held the same address a.head did. When that Node is deleted, b is left holding a dangling pointer to it.

What count is actually for

You might reasonably wonder: if I can already walk the whole chain with head alone, what is count doing there?

Direct answer: traversal does not need count. This loop visits every node and never looks at it:

Node *cur = head;
while (cur != NULL) {
    cout << cur->item;
    cur = cur->next;
}

count is a stored answer to a question you would otherwise have to walk for — "how many items are in this list?"

Without countWith count
How many items?walk the whole chain and tallyread one number, instantly
What it coststime, proportional to the lengthdiscipline — every insert and remove must update it

That second cost is why count matters in an exam: forgetting to update it is the single most-seeded bug in find-the-bug questions. A list whose count disagrees with its chain is broken even though every node is intact.

Critical Exam Trap • A Walking Pointer Never Uses new

A traversal pointer borrows a node that already exists. Allocating one first creates a node that the very next line abandons — unreachable, never freed, a memory leak.

Correct (earns marks)Incorrect (loses marks)
Node *cur = head; Node *cur = new Node;
cur = head;

Critical Exam Trap • Shallow Still Makes New Boxes

A shallow copy is not "nothing gets copied." b genuinely gets its own count box and its own head box, at its own addresses. What it does not get is its own Nodes. Drawing a and b sharing one head box is a different (and wrong) picture.
