Functions inside a struct

Lesson 2 taught you that a struct holds data fields. That was true, but incomplete. A struct can also hold functions. That's the one new idea in this lesson — nothing else.

What you already know

struct Student {
    string name;
    int    mark;
};

Two data fields. To do anything with a Student, you'd write a separate, outside function and hand the student to it. One small thing first: a parameter can be a whole struct, written just like any other type — Student s is a parameter holding a copy of an entire Student, exactly as int n holds a copy of an int:

struct Student {
    string name;
    int    mark;
};

bool passed(Student s) {     // an OUTSIDE function — takes a Student
    return s.mark >= 50;
}

Student a;
a.mark = 88;
passed(a);                    // hand a to the function

The new idea

You can move that function inside the struct:

struct Student {
    string name;
    int    mark;
    bool   passed();      // a function that BELONGS to Student
};

Now passed is a member function — it belongs to Student the same way name and mark do. And it is called the same way too, with a dot:

Student a;
a.mark = 88;

a.mark;        // read a data member — dot
a.passed();    // call a member function — dot, plus ()

A microwave, not a workshop. The outside version is a workshop: the food sits on the counter, and you carry it over to a separate machine to heat it. The member-function version is a microwave with the food already inside — the heating button is part of the appliance holding the food. You don't hand the food to the button; you press the button on the thing that already has it.

Why it matters (one reason)

A member function doesn't need the struct passed in as a parameter, because it's already inside one. Look at the parameter lists:

Outside functionMember function
bool passed(Student s)bool passed()
Called as passed(a)Called as a.passed()
Reads s.markReads mark — plainly, no prefix

Inside a member function, writing mark automatically means "the mark of whichever Student this function was called on." That's why the parameter list is empty — the struct isn't passed in, it's already there.

This is the single reason the course's List functions have such short parameter lists. find(int) takes only a position, not a position and a list — the list is whichever one you called it on.

Quick check — given struct Student { string name; int mark; bool passed(); }; Student a;, how do you call passed on a?

Right — a member function is reached through the struct variable with a dot, exactly like a data field, but with () because it's a call.
passed(a) is how you'd call the outside version. Once the function lives inside the struct, you reach it the same way you reach a.mark — through the variable, with a dot.

Second check — one word: the outside version needed (Student s) as its parameter. What is the member version's parameter list?

Exactly — empty. The Student doesn't need passing in, because the function is already inside one.
Compare the two signatures in the table above. What did the member version drop, and what made it unnecessary?
