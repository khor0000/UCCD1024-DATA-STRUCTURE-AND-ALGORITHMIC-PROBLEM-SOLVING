The List container

In Lesson 6 you built a chain by hand, juggling n1, n2, n3 and head as loose separate variables. That works for three nodes and falls apart at thirty. The one idea in this lesson: a whole chain of any length can be tracked by exactly two variables, and List is just a struct that holds those two.

"Container" just means this: a struct that keeps track of a collection for you and hands you the operations for working with it. You talk to the container — list.insert(...), list.get(...) — and never handle the individual nodes yourself. That's the entire word. List is a container; a Node is not.
struct List {
    int   count;    // how many nodes are in the chain right now
    Node *head;     // the address of the first node (NULL if empty)
    // ...member functions, one per lesson from here on
};

A treasure hunt organizer. You don't memorize every stop of the hunt. You know two things: where stop 1 is, and how many stops exist. Anyone who wants stop 4 asks you, and you walk the chain from stop 1 counting as you go. Two facts, any length of hunt.

Read the two left boxes carefully — together they are the whole List. Note they're drawn as two single-cell boxes, not as one two-cell box: a two-cell box in these lessons always means a Node, and the List is not a Node.

  • count lives at 0x8FC and holds 3. A plain int. It is not a pointer and points at nothing.
  • head lives at 0x900 — its own separate variable, sitting right next to count in memory — and holds the value 0x500, which is box1's address. Same two-box relationship as every pointer since Lesson 1: the variable is one box, the Node it refers to is a completely separate box elsewhere.
  • Boxes 1, 2 and 3 are not inside the List. The List doesn't contain the nodes — it only knows where the chain starts. Box2 and box3 are reachable only by following next from box1.

That's the whole container. Every List function you'll meet from here on does its work by starting at head and walking, exactly like the traversal loop you traced in Lesson 6c.

What count = 3 actually counts

count is a plain tally of how many nodes exist. Nothing more. count = 3 means three nodes — not four, and there is no node zero.

You might reasonably wonder: so are the nodes numbered 0, 1, 2 or 1, 2, 3? This is worth getting straight now, because it is the single most common thing to carry in wrongly from outside reading.

What count counts — and where position 1 is

count = 2 means two nodes. Not three. count is a quantity — it answers "how many?", and never "what is the last position?"

Those two questions give different numbers in most languages, because most things are numbered from zero. This course numbers list positions from 1. find(1) returns the head. There is no position 0 anywhere in this List.

If you have watched any, your instinct is calibrated to the other convention — and insert, remove, get and set all take a position, so the off-by-one lands on every one of them.

Critical Exam Trap • Positions Start At One

count is how many nodes exist, and the last node is at position count, not count - 1. A loop written array-style walks one node past the end or stops one short.

The empty list

List has a constructor (Lesson 6f), so a brand-new list starts in a known state automatically:

List::List() {
    head  = NULL;   // no first node yet
    count = 0;      // nothing in the chain
}
0x8FC
0
list.count
0x900
NULL
list.head

No arrow, because there's nothing to point at. An empty list is exactly two things: head == NULL and count == 0, and they are always true together. A correct list can never have count nonzero while head is NULL, or the reverse. Burn that pairing in now — "did head and count stay in sync?" is the question behind nearly every bug you'll be asked to spot.

Quick check — what are head and count for a freshly-constructed, empty List?

Right — an empty list has no first node (head is NULL) and zero items (count is 0), always together.
An empty list has genuinely nothing — no placeholder Node — and count must be 0 whenever head is NULL.

Second check — a List's count says 3, but you have no idea where the chain starts. Which of the two fields did you lose?

Exactly — count only tells you how many nodes exist; head is the only way back to any of them. Lose head and all three nodes are unreachable forever.
Look at the first diagram: which of the two boxes is the only thing joining the List to the chain?

On paper — this is the part that counts

Everything above was reading. Reading a diagram is not the same skill as producing one, and the paper asks you to produce. Close this page for the next two tasks.

On paper • two drawings

1. Write out the struct List declaration from memory — both fields, with their types.
2. Draw a List holding the chain 10 → 20 → 30. Show count and head as two separate one-cell boxes, each with its own address, and draw the arrow from head to the first node.
3. Draw the same picture for an empty list.

reveal — the declaration 
struct List {
    int   count;
    Node *head;
};

Four things to check in what you wrote. The closing brace is followed by a semicolon. If the constructor is declared too, it is written List(); inside the braces and defined separately outside as List::List() { ... } — that outer one takes no semicolon. count is an int — no star. head is a Node * — it must have the star, because it holds an address, not a Node. If you wrote Node head; you declared a whole node sitting inside the List, which is a different structure entirely.

reveal — the two drawings

The full list: count holds 3, head holds 0x500, arrow to box1, and the three nodes chained by next with NULL at the end — the first diagram in this lesson. The empty list: count holds 0, head holds NULL, no arrow, no nodes at all — the second diagram.

Mark yourself on three things only: are count and head drawn as two separate boxes; is each node a two-cell box; and does the last node's next say NULL rather than being left blank.

Critical Exam Trap • The Semicolon After A Struct

A struct declaration is a statement, so its closing brace is followed by a semicolon. A function definition is not a statement, so its closing brace is bare. The two braces look identical on paper and the rule is opposite for each.

Two ways to draw the List — both accepted

The diagrams above draw count and head as two separate one-cell boxes. You may instead draw one box labelled List with the two fields written inside it. Both are correct, and the second is closer to the truth — the two fields really do sit together inside one struct.

Whichever you pick, the arrow must leave head specifically — not the middle of the box, and never count. count is a plain number and points at nothing.

Critical Exam Trap • Write NULL, Not null

The last node’s next is the C++ token NULL, in capitals. null, Null and nul are not C++ — that spelling belongs to Java and JavaScript. Leaving the cell blank is also wrong: blank means "not set yet", NULL means "deliberately the end of the chain". Those are two different states and the paper distinguishes them.

Correct (earns marks)Incorrect (loses marks)

Critical Exam Trap • The List Is Not A Node

In a hand-drawn answer, a two-cell box means a Node and a one-cell box means a plain variable. Drawing the List as one two-cell box says "the List is a node holding an item and a next" — a different structure from the one you were asked for.
