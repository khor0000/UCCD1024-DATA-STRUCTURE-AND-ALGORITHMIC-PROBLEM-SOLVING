The constructor

One member function in this course's code looks broken at first glance:

struct Node {
    int   item;
    Node *next;
    Node(int);        // ← no return type. And named "Node"?
    Node();           // ← same again
};

Every other function so far started with a return type — bool passed(), Node *find(int). These two have none, and they're named exactly the same as the struct. That's not a typo. A member function with the struct's own name and no return type is a constructor, and that's the one idea in this lesson.

What it does

A constructor runs automatically, once, at the moment a struct variable is created. You never call it by name. Its job is to fill in the fields so the variable starts out in a sane state instead of holding leftover garbage.

The factory reset on a new phone. You don't press a "set up the phone" button — the moment the phone is switched on for the first time, it puts itself into a known starting state. Nobody calls it; it just happens once, at creation. A constructor is that first boot.

Node's two constructors

Node::Node(int newItem) {   // used when you write: new Node(10)
    item = newItem;
    next = NULL;
}

Node::Node() {              // used when you write: new Node
    item = 0;
    next = NULL;
}

Same Struct:: pattern from last lesson — Node::Node means "the Node constructor belonging to struct Node." The only structural difference from an ordinary member function is the missing return type.

So back in Lesson 5, when you wrote Node *n1 = new Node(10);, this is what actually happened: new reserved the memory, and then the Node(int) constructor ran on that fresh memory, setting item = 10 and next = NULL. Two constructors exist so both of these work:

new Node(10)Node(int)item = 10, next = NULL

Notice both constructors set next = NULL. That's why you've never had to write n3->next = NULL; by hand when building a chain — the constructor already did it. A node fresh out of new is always a complete, terminated one-node chain.

Why "no return type" is not an oversight

An ordinary function hands something back to whoever called it. Nobody calls a constructor, so there's nobody to hand anything to — it runs on the new variable and that's the end of it. A return type would have nothing to describe. Writing void Node::Node() is actually a compile error, not just bad style.

Quick check — when does Node::Node(int) run?

Right — creation time, automatically, exactly once per node. You never write the call.
A constructor isn't something you call by name and isn't tied to field access — it fires once, on its own, at the moment the variable comes into existence.

Second check — one word: after Node *p = new Node(7);, what is the value of p->next?

Exactly — NULL, set by next = NULL; inside Node::Node(int), not by anything you wrote.
Look at the body of Node::Node(int newItem) above — it sets two fields, and you only supplied one of them.
