Above the call vs below the call

Retrieval check • 20 seconds

From Lesson 24b: in p(3), why is the very last number printed a 3?

reveal

Because p(3) kept its own n = 3 the whole time it was frozen. When it finally unfreezes and runs line B, it prints its n.

The one idea that decides the output

Look at where the cout sits relative to the self-call:

  • A line above the self-call runs on the way down — big n first.
  • A line below the self-call runs on the way back up — and because copies resume in reverse, that comes out reversed.

Same three-line skeleton, cout moved. This is the whole difference:

print, then recurse

void r(int n) {
    if (n == 0) return;
    cout << n << " ";
    r(n - 1);
}

r(4) → 4 3 2 1
Print is above — all of it on the way down.

recurse, then print

void s(int n) {
    if (n == 0) return;
    s(n - 1);
    cout << n << " ";
}

s(4) → 1 2 3 4
Print is below — all of it on the way back up, reversed.

The p from Lessons 24 & 24b has a print both above and below the call, so every n is printed twice — once going down, once coming up. That is why p(3) → 3 2 1 1 2 3 reads the same forwards and backwards.

“Line A” and “line B” are names for this function only. Most recursive functions don’t have both. Many have work only before the call (like r below), or only after (like s), or the work isn’t a cout at all — it is return n + f(n - 1), where the + happens on the way back up. There is no standard exam term for the two positions; “before the call” / “after the call” is all you need.

Watch each one execute — where does the work happen?

Step through both. Same idea as Lesson 24b: a copy appears when its call runs, and vanishes when it returns.

r — the cout is before the call

s — the cout is after the call

“But r is just a loop.” You’re right. r, with all its work before the call, prints 2 1 — exactly what for (int i = 2; i >= 1; i--) cout << i; prints. No visible difference, and a compiler can turn that kind of recursion straight into a loop. The difference shows the moment there is work after the call: s prints 1 2 — reversed — and a for counting up can’t do that without extra effort. s gets the reverse for free because every paused copy is holding its place to run its after-work later. That stack of paused copies is the thing a loop does not have. So: work only before the call → behaves like a loop; any work after the call → needs the stack.
Critical Exam Trap • The Base Case Prints Nothing, But The Trip Back Does

Two ways to drop these marks: (1) stopping your trace at the base case — the lines below the self-call still have to run for every frozen copy on the way back up; (2) miscounting the prints. Count first: print only above the call, went down n levels → expect n numbers. Print above and below → expect 2n.

Correct (earns marks)Incorrect (loses marks)
p(3) → 3 2 1 1 2 3 (six: line A ×3, line B ×3) p(3) → 3 2 1 (stopped at the base case)

Drills — closed book, on paper

Drill 1 • trace

Write the exact output of q(4);

void q(int n) {
    if (n == 0) return;
    q(n - 1);
    cout << n << " ";
}
reveal

1 2 3 4. The self-call is above the print, so nothing prints on the way down; each copy prints once on the way back up, smallest first. Four levels, one print each = four numbers.

Drill 2 • trace, print above AND below

Write the exact output of g(3); — neither cout prints a space, so watch the spacing.

void g(int n) {
    if (n == 0) return;
    cout << "(" << n;
    g(n - 1);
    cout << n << ")";
}
reveal

(3(2(11)2)3). Going down prints (3, (2, (1; the base case prints nothing; coming back up prints 1), 2), 3). The two 1s touch — (1 then 1) is (11) — because no statement emits a space.
