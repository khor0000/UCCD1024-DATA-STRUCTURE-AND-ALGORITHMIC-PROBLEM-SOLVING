Tracing a queue's printed output

Q4a hands you a main() full of enqueue, dequeue and cout calls and asks for the exact text it prints. You run the code by hand, keeping a running picture of the queue, and write down what each cout produces — in order.

Retrieval check • before reading on

From Lesson 20, no scrolling: which end does enqueue add to, which end does dequeue take from, and what does dequeue(x) do to the variable x?

reveal

enqueue adds at the tail (back). dequeue removes from the head (front). dequeue(x) copies the removed item into x through the reference parameter — after the call, x holds whatever just left the front.

The method — one running picture

Draw the queue as a row, front on the left, back on the right. Walk the code top to bottom. For each line:

  1. q.enqueue(v); — write v at the right end.
  2. q.dequeue(x); — cross off the left-most value; that value is now in x.
  3. cout << ...; — write down exactly what it prints, then carry on.

The queue picture is your working; the list of cout outputs, in order, is your answer.

Worked example

Queue q;
int x = 99;

q.enqueue(3);
q.enqueue(7);
q.enqueue(1);
q.dequeue(x);   cout << x << " ";
q.enqueue(5);
q.dequeue(x);   cout << x << " ";
cout << q.size() << " ";
q.dequeue(x);   cout << x;

Critical Exam Trap • dequeue On An Empty Queue Does Nothing To x

Look at Queue::dequeue: if (empty()) return false; is the first line. If the queue is empty it returns immediately — it never reaches itemExtracted = head->item;. So x keeps whatever value it already had. A cout << x; right after prints that stale value, not a new one.

Queue q;
int x = 0;
q.enqueue(8);
q.dequeue(x);   cout << x << " ";   // x = 8   -> prints "8 "
q.dequeue(x);   cout << x << " ";   // queue EMPTY: x stays 8 -> prints "8 "

Output: 8 8 — not 8 0, and not an error.

Correct readingWrong reading
empty dequeue → x unchanged, prints the old value empty dequeue → x becomes 0 / NULL / errors
FIFO, every time. dequeue always takes the value that has been in the queue longest — the left end of your row. It never takes the most recent one. If you find yourself removing from the right, you are tracing a stack, and every answer will be reversed.

Queue holds 4 → 8 → 15 (4 at the front). dequeue(x) is called twice. What is x afterwards?

Right — first call takes 4, second takes 8. x holds 8, queue is now just 15.
Each dequeue takes from the front. First 4 leaves, then 8 leaves. What is in x after the second?

True or false: calling dequeue(x) on an empty queue sets x to 0.

False — it returns false before touching x. x keeps its previous value.
Re-read dequeue: if (empty()) return false; is the first line. Does it ever reach the line that writes x?
