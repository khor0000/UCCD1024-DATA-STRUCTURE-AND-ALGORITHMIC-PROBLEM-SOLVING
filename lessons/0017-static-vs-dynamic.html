Static vs dynamic — the four ways to make an object

Static means the object is a plain variable. Dynamic means the object is made with new. That is the entire distinction. You already write both — you just did not know the two words for them.

You are not missing a concept here. In your drill you produced three of the four forms correctly, unprompted, and explained . vs -> in your own words without an error. This lesson gives you the vocabulary for what you already do, and the one form you are missing.

The word "static" is badly chosen — read this first

You might reasonably wonder: doesn't static mean something else in C++?

Yes, and that is why this trips people. C++ has a keyword static, and it means something different — a variable shared across all objects. Ignore that keyword completely. It is not on your paper.

When your lecturer says "static creation", he means only this: the object is an ordinary variable. Nothing is shared, no keyword is typed. If the word bothers you, read it as "automatic" — that is the term the C++ standard actually uses.

PhraseWhat it means here
static creationbook b; — a plain variable. No new.
dynamic creationbook *p = new book; — made with new.
the static keywordUnrelated. Not examined. Forget it.

The physical difference

A desk drawer versus a rented locker.

Static is your desk drawer. It comes with the desk. You do not ask for it and you cannot give it back. When you leave the room — when the function ends — the drawer goes with the desk. Everything in it is gone. You did not have to tidy up.

Dynamic is a rented locker. You go to the desk and ask for one: that request is new. They hand you a key, not the locker — the key is the pointer. The locker is nowhere near your desk. Leave the room and the locker stays rented, still holding your things. It stays rented forever until you hand the key back, and handing it back is delete.

Almost everything you write wants a drawer. The locker is for the rare thing that has to outlive the room it was made in — and there is a section below on exactly when that happens.

The four forms — all of them

Two choices, made independently: static or dynamic, and default or parameterised constructor. Two times two is four.

// ── STATIC (a plain variable) ───────────────────────────

book b1;                          // default ctor
book b2("Dune", 412);             // parameterised ctor   ← the one you missed

b1.title = "HelloWorld";          // dot, because b1 IS a book


// ── DYNAMIC (made with new, held by a pointer) ──────────

book *p1 = new book;              // default ctor
book *p2 = new book("Dune", 412); // parameterised ctor

p1->title = "Splatoon";           // arrow, because p1 is a POINTER to a book

The form you did not write: book b2("Dune", 412); — static, with arguments. No =, no new, arguments go straight after the variable name.

You might reasonably wonder: why isn't it book b2 = book("Dune", 412);? That also works, but nobody writes it, and your lecturer does not. Learn the short form.

The * is not optional, and it is the easiest mark to drop. new book does not hand you a book — it hands you an address. So the variable receiving it must be declared as a pointer:

book b3  = new book;   // ✗ won't compile. b3 is a book; new gives an address.
book *b3 = new book;   // ✓ b3 is a pointer to a book.

You might reasonably wonder: why does the type change when the constructor didn't? Because new is what changed, not the constructor. Every single new in C++ produces an address. An address must be stored in a pointer. The * belongs to the new, so if you write one, write the other.

And a trap worth knowing now: book b1(); with empty brackets is wrong. C++ reads it as declaring a function called b1 that returns a book. For the default constructor, write no brackets at all: book b1;. Note this does not apply to new book() — brackets there are fine.

Critical Exam Trap • The Star Belongs To The new

new hands back an address, never an object. Whatever receives it must be declared as a pointer. If you write new, write the *.

Why one uses . and the other uses ->

You answered this correctly already. Your words:

"The one using . is because it is the object — if an object needs to access its field, use dot. The other uses -> because it is a pointer. The -> means follow the address and look into it, access the field next to the operator."

That is right, and it is the whole rule. The operator follows the variable's type, not your intent.

The variable is…UseBecause
a book.The book is right here. Open it.
a book *->You hold a key. Go to the locker first, then open it.

Draw the state

Stage 1 — book b2("Dune", 412); · static. One box. The box is the book.

   b2  @ 0x500
   ┌────────────────┬────────────┐
   │ title: "Dune"  │ pages: 412 │      b2.title  ← dot. Nothing to follow.
   └────────────────┴────────────┘

Stage 2 — book *p2 = new book("Dune", 412); · dynamic. Two boxes.

   p2  @ 0x500              the book @ 0x8A0  (the heap — far away)
   ┌──────────┐             ┌────────────────┬────────────┐
   │  0x8A0   │ ──────────► │ title: "Dune"  │ pages: 412 │
   └──────────┘             └────────────────┴────────────┘
    the key                  the locker

   p2->title  ← arrow. Follow 0x8A0 first, then read the field.
   p2.title   ← WRONG. p2 has no field called title. It holds an address.

The pointer and the object are never the same box. Draw two boxes every time and the operator chooses itself.

So when do you actually use new?

Default to static. Use new only when the object must still exist after the function that made it has finished.

Everything you have written so far lives and dies inside main. So for now: use static. That is the honest answer to your question today.

The one case where static fails

Forget linked lists for a moment. Here is the whole problem, using only book.

A drawer belongs to a room. When you leave the room, the drawer goes. A function is a room.

book* makeBook() {
    book b("Dune", 412);   // a drawer inside this function
    return &b;             // hand out the drawer's address
}                          // function ends — the drawer is destroyed

The caller now holds an address to a book that no longer exists.

Stage 1 — inside makeBook. The book exists.

   b @ 0x7F0   (inside makeBook's drawer)
   ┌────────────────┬────────────┐
   │ title: "Dune"  │ pages: 412 │
   └────────────────┴────────────┘

Stage 2 — makeBook returns. The drawer is gone. The returned address points at nothing.

   the caller holds 0x7F0        0x7F0  ── destroyed ──
   ┌──────────┐
   │  0x7F0   │ ─────►   ✗   reading it now is undefined behaviour
   └──────────┘

Swap one word and the problem disappears:

book* makeBook() {
    book *b = new book("Dune", 412);   // a rented locker, not a drawer
    return b;                          // hand out the key
}                                      // function ends — the locker stays rented

The pointer b dies. The book does not. That is the only job new has.

The rule for your paper, in one line: if the question says "dynamically" or "using new", use new. Otherwise use static. The question tells you. You are not asked to decide.

Later, when you meet linked lists, one more case joins the list: a list node is built inside a function and must survive after it returns, so nodes always use new. You do not need that yet. It arrives with the lesson that teaches lists.

What the exam does with this

Q1a gives you code and asks for the output. The marks are lost on ./-> and on which constructor fired. Q2a asks you to write it. Both want the four forms above and nothing more.

You might reasonably wonder: do I need delete? For the midterm, no question asks for it. Write it if a question mentions memory; otherwise do not spend paper on it. Every new in real code needs a matching delete — the rented locker — but it is not what is being marked here.

Quick check

A line reads book b3("Dune", 412);. Which is true?

Correct. No new, so it is static. Arguments are present, so the parameterised constructor runs. b3 is a book, not a pointer, so you access fields with b3.title.
Check for the word new first — it is absent. Then check for arguments — they are present. Then ask what type b3 is.

book *p = new book; — write the expression that reads its pages field.

Yes. p is a pointer, so you follow the address first.
What type is p? Draw its box and see whether it holds the book or an address to it.
