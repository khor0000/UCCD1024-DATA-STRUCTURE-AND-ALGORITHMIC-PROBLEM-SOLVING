What a queue is

A queue is a line at a shop counter. New items join at the back. Items leave from the front. The first one in is the first one out — FIFO, first-in-first-out.

Midterm Q4a hands you queue code and asks for its printed output. It does not ask you to write the queue. This lesson is the model you trace with; Lesson 21 is the output drill.

The whole shape, before any code

A queue has two ends, and one operation works at each:

OperationWorks atPlain meaning
enqueue(x)the tail (back)join the line
dequeue(x)the head (front)leave the line, and hand back who left
empty()—is the line empty?
size()—how many in the line

The bank queue. You walk in and stand at the back — that is enqueue. The teller calls the person at the front, who leaves — that is dequeue. Nobody is served out of turn, and nobody joins in the middle. The person who waited longest is served next.

The struct — recognise it in the exam

This is a linked list with a pointer to both ends. Same Node as your linked-list lessons (item + next); the extra piece is tail.

using type = int;

struct Queue {
    int    count;
    Node  *head;    // the front — dequeue takes from here
    Node  *tail;    // the back  — enqueue adds here
    Queue();
    bool empty();
    int  size();
    bool enqueue(int);     // add to the back
    bool dequeue(int&);    // remove from the front
    Node *find(int);
};
Why tail? A plain linked list only tracks head. To add at the back you would have to walk the whole chain first. Keeping a tail pointer means enqueue can jump straight to the last node — no walk. That is the one structural difference from the list you already know.

enqueue — join the back

bool Queue::enqueue(int newItem) {
    Node *tmp = new Node(newItem);
    if (!tmp) return false;

    if (empty()) {              // first person in the shop
        head = tail = tmp;
        count++;
        return true;
    }
    count++;
    tail->next = tmp;          // old last node points at the newcomer
    tail = tmp;                // tail now names the newcomer
    return true;
}

Two cases, same as insert: the empty queue (the newcomer is both front and back), and the normal case (hook it after the current tail, then move tail).

dequeue — leave the front

bool Queue::dequeue(int &itemExtracted) {
    Node *cur = head;
    if (empty()) return false;

    count--;
    itemExtracted = head->item;   // hand back who is leaving
    head = head->next;            // front moves to the next person
    free(cur);                    // release the old front node
    if (count == 0) tail = NULL;  // queue now empty — tail must let go too
    return true;
}

This is exactly remove position 1, plus one line: itemExtracted = head->item; copies the leaving item out through the reference parameter before the node is freed.

The reference parameter is the receipt. You call dequeue(x). The queue removes the front person and writes their name onto your variable x. After the call, x holds whoever just left. That is how the caller finds out what came off the queue — dequeue itself only returns true/false.

One trace: enqueue(30) then dequeue(x) on a queue holding 10 → 20

Critical Exam Trap • Which End Each Operation Touches

enqueue adds at tail. dequeue removes at head. Swap them in your head and every output comes out reversed — you would be modelling a stack, not a queue.

Queue (FIFO) — this lessonStack (LIFO) — not this
add at back, remove at front
order preserved: in 1 2 3, out 1 2 3		 add and remove at the same end
order reversed: in 1 2 3, out 3 2 1

Queue holds 10 → 20 → 30 (10 at the front). You call dequeue(x) once. What does x hold afterwards?

Right — the front leaves first. x holds 10, queue is now 20 -> 30.
dequeue takes from the head, and the head is the front — the oldest item.

One word: which pointer does enqueue move?

Yes — the newcomer becomes the new back of the line, so tail moves to it.
New items join the back. Which pointer names the back?
Produce it • closed book

On paper: (1) draw a queue holding 7 → 4 with head and tail labelled. (2) Show it after enqueue(9). (3) Show it after dequeue(x), and write what x holds. (4) In one line each, say what enqueue does and what dequeue does.

reveal answer

(1) head → [7|•] → [4|NULL] ← tail

(2) after enqueue(9): head → [7|•] → [4|•] → [9|NULL] ← tail. count 3.

(3) after dequeue(x): head → [4|•] → [9|NULL] ← tail. x holds 7. count 2.

(4) enqueue: make a node, hook it after tail, move tail to it. dequeue: copy head->item into the reference parameter, move head forward, free the old front node.
