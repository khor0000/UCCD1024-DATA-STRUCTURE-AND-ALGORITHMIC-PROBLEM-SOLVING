remove: the general case

To remove a node that is not the head: walk to the node just before it, point that node past the target so the chain skips it, then hand the skipped node's memory back.

cur = head; is the save. head is the only pointer to the doomed node; once head moves forward, that node is unreachable and there is nothing left to give free(). (Lesson 11.)

The whole shape of remove — four steps, always this order

  1. Check the position is real. from must be 1 to count — you can only remove a node that exists.
  2. Walk to the node just before the target with find(from-1). (Position 1 has no "before" — that was Lesson 11.)
  3. Re-route. The node before the target points past it, to whatever came after.
  4. Hand the memory back with free() — after reading anything you still need from the doomed node.

This lesson is steps 2–4 for positions 2 to count. Here is the whole function, with this lesson's part boxed:

bool List::remove(int from) {
    Node *pre, *cur;

    if (from < 1 || from > count) return false;   // step 1

    if (from == 1) {                              // Lesson 11
        cur = head;
        head = head->next;
        count--;
        free(cur);
        return true;
    }

    // normal case   ←←← THIS LESSON
    pre = find(from-1);      // node right before the target
    cur = pre->next;         // the target itself
    pre->next = cur->next;   // pre skips straight over cur
    free(cur);              // give cur's memory back
    count--;
    return true;
}

This is copied line-for-line from Lecture 4's List.cpp. Reproduce this order on paper.

Taking one link out of the middle of a chain. Hold the link just before the one you want gone (pre). Unclip its far end and clip it instead onto whatever the unwanted link was joined to (cur->next). The unwanted link now dangles free, joined to nothing — safe to throw away.

Why find(from-1), not find(from)

A singly linked list has forward arrows only. To make the chain skip a node, you must change the next field of the node before it — that is the only node whose arrow points at the target. So you walk to from-1, not from. Same reason insert's general case used find(at-1).

Critical Exam Trap • Read cur->next Before free(cur)

pre->next = cur->next; must run before free(cur);. It needs to read the doomed node's next field to know where pre should point. Free the node first and that field is gone — reading it is a use-after-free, and the chain past the removed node is lost.

You might reasonably wonder: Lesson 11 wrote count-- before free, this one writes it after — which is right? Both. They are copied straight from Lecture 4, which genuinely orders them differently in the two branches. It does not matter: count is a plain number living in the List box, not inside the node. free(cur) only touches the node. So count-- and free(cur) never interfere, in either order. The order that does matter is the one in the trap above — the read before the free.
