Recursion vs the loops you already trace

Retrieval check • 20 seconds

From Lesson 24c: a recursive function prints only below the self-call. Does its output come out in order, or reversed?

reveal

Reversed — the copies resume in reverse order (last frozen, first to finish), so the smallest n prints first.

Same job, different trace

Q1a hands you a for / while / do-while loop and asks for its output. Q4b hands you a recursive function and asks for its output. Same skill — predict output by hand — but you trace them differently, and the difference is exactly the frozen-copies idea from Lesson 24b.

A loop (Q1a)Recursion (Q4b)
Variables One set. Each pass overwrites them — the old i is gone for good. A fresh n per call. The older ones don’t vanish — they sit frozen, each holding its value, waiting to resume.
How you trace it One running tally. Top to bottom of the body, then jump back to the top. Repeat until the condition fails. Go all the way down first (every line above the call, for every copy), hit the base case, then come back up running every line below the call — in reverse.
Shape of the output One value produced per pass, in pass order. Print only above the call → like a loop. Print above and below → each value appears twice, second half reversed.
Shortcut. If a recursive function’s only cout is its last line (nothing below the call), trace it exactly like a loop — one value per level, no “coming back up” half to worry about.

“A for loop can count up or down too — so what’s the real difference?”

True — the direction is not the difference. And you are right that a function like s (print only after the call) does exactly what a for loop does. For that function there is no real difference.

The difference is what a single loop cannot do: pause half-way through one pass, run every deeper pass to the end, then come back and finish the paused pass. A loop body always runs top-to-bottom and then restarts — it never stops in the middle to go do something else.

void g(int n) {
    if (n == 0) return;
    cout << "(" << n;   // on the way DOWN
    g(n - 1);
    cout << n << ")";     // on the way BACK UP, with the SAME n
}
// g(3)  ->  (3(2(11)2)3)

g does one thing before the call and a different thing after it, remembering its n across the gap. One for loop visits each value once — to get this you would need two loops, or a stack. Recursion gives you the “pause and come back” for free, as many levels deep as you like.

At the variable level. A loop has one box for i, overwritten every pass. Recursion makes a new box for n on every call, and while the calls are nested all those boxes are alive at once — that stack of remembered values is the thing a loop does not have. (Lesson 24b’s note, “how can n be 3 and 2 and 1 at once”, is the same point.)

You trace a loop with one running tally. Why can’t you always do that for recursion?

Right. A loop reuses one i; recursion can have p(3), p(2), p(1) all alive with different n, which is why the trace table needs a column each.
Recursion does have variables and does print. The catch is that several copies are alive at once, each with its own n — one tally can’t hold them all.

If you ever can’t tell whether to trace something as a loop or as recursion — ask. The tell is one word: does the function’s body contain its own name?
