Why a self-calling function isn’t infinite

A recursive function is a function that calls itself. The midterm never asks you to write one. It gives you one and asks either “what is the output of p(3)?” (Q4b, you trace it) or “what does this function compute?” (Q4c, you describe it). Both are reading jobs.

Where this sits. You can already predict the output of a for / while / do-while loop by hand (Lesson 18, Q1a). Recursion output is that same skill with one extra twist, which Lesson 24c names. This 5-part chain gets you there one step at a time.

The function this chain traces

void p(int n) {
    if (n == 0) return;      // the STOP line
    cout << n << " ";        // line A
    p(n - 1);                // calls a fresh copy of p, with n one smaller
    cout << n << " ";        // line B
}
“Line A” and “line B” are labels for this function only. Not every recursive function prints both before and after its call — some do only one, some do neither. Lesson 24c shows what changes when the print is only on one side.

The objection — “surely that never ends?”

If p needs p to finish before p can finish, nothing ever finishes. That is the honest reaction, and it is worth answering before anything else.

It is not the same p. When p(3) reaches the line p(n - 1), that starts a brand-new, separate copy of the function — its own n, its own place in the code. p(3) freezes on that line and waits. When the new copy has completely finished, p(3) unfreezes and runs its next line.

Two things guarantee it stops, and every exam recursion has both:

ThingIn the codeIts job
The stop line
(real name: the base case)		 an if that returns without calling p again — if (n == 0) return; the bottom. A copy that hits this stops and hands control back up. Nothing below it runs.
The shrinking argument every self-call passes something smaller — p(n - 1) drives every copy one step closer to the base case, so it is always reached.

Remove either one and it really is endless — the program keeps making copies until it runs out of room and crashes (a stack overflow). Both present, and it always stops.

The picture: a stack of clerks

Clerk 3 has a form. Halfway down, one step says: “hand a fresh blank copy to a new clerk, write n one smaller on it, and wait for them to hand it back before carrying on.”

Clerk 3 hands to Clerk 2 and freezes, holding n = 3. Clerk 2 hands to Clerk 1, freezes holding n = 2. Clerk 1 hands to Clerk 0. Clerk 0’s form says “if n is 0, stop — hand back nothing.” Clerk 0 is the base case: the floor of the stack, the one who hands off to nobody.

Then they unfreeze in reverse: Clerk 1 finishes, then Clerk 2, then Clerk 3. Last to freeze, first to resume. Each still has their own n on their own form.

In this function, which line is the base case?
void h(int n) {
  if (n <= 1) return;  — line 1
  cout << n;  — line 2
  h(n - 2);  — line 3
}

Right. The base case is the branch that ends the function without another self-call. Line 3 is the shrinking argument; line 2 is just the work.
The base case is the one that stops the recursion — it returns without calling h again. Look for the if with a bare return.
