What is a function?

A function is a named, reusable block of code. You write it once; you can run it — "call" it — as many times as you want, from wherever you want, just by writing its name followed by ().

A vending machine. You put coins in (that's input), the machine does something inside that you don't have to think about, and it may hand you back a snack (that's the output) — or, if it's a machine that just plays a jingle, hand you back nothing at all. Every function is a small machine like this: give it inputs, it runs its code, it may or may not hand something back.

The four parts of a function

int add(int a, int b) {
    return a + b;
}
PartHereMeaning
return typeintthe type of thing this function hands back when it's done
nameaddwhat you'll type to call this function later
parameters(int a, int b)the inputs — coins you must put in every time you call it
body{ return a + b; }the code that runs, every time, using whatever was put in

To actually run it — to call it — you write its name with real values in place of the parameters:

int result = add(3, 5);   // runs the body with a=3, b=5
cout << result;           // 8

a and b only exist while add is running. Each call gets its own fresh a and b — call add(3, 5) and later add(10, 1), and they don't interfere with each other at all.

Quick check — in int add(int a, int b) { return a + b; }, what does (int a, int b) represent?

Right — parameters are the inputs. What it hands back is a separate thing (the return type + the return statement).
Parentheses after the function name always hold the inputs — what you must supply every time you call it.

void: a machine with no snack

Not every function hands something back. If a function's job is just to do something — print to the screen, change a value, attach one box to another — it has no output, and its return type is void. void literally means "nothing."

void greet(int times) {
    for (int i = 0; i < times; i++) {
        cout << "hi ";
    }
}   // no return statement needed — there's nothing to hand back

greet(3);   // prints "hi hi hi ", hands nothing back

Notice: greet(3) is called on its own line, not assigned to anything (int result = greet(3); would be an error) — because there's no snack to catch.

Second check — what return type do you write for a function that only prints something and hands nothing back?

Exactly — void means "this function hands nothing back."
Look at greet above — what word sits where int sat in add's signature?

void attach(Node *ptr) {
    Node tmp;
    tmp.item = 10;
    ptr->next = &tmp;
}

voidthis function hands nothing back — its job is just to do something

Nothing about the dangling-pointer bug from Lesson 5 has changed — this is purely "here's how to read the wrapper around it."

One thing to file away, not worry about yet: later lessons will show functions written as List::insert(...) — that just means "this function lives inside the List struct," same idea as attach living on its own. You don't need struct-attached functions to understand anything on this page.

Ask if any of the four parts (return type, name, parameters, body) still feel shaky before moving on — everything from here on assumes you can read a function signature at a glance.
