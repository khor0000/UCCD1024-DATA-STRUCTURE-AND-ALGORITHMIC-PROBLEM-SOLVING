Addresses behind the arrows

Lesson 6 showed n1, n2, n3 as separate boxes from the Node boxes they point to — same two-box shape Lesson 1 used for x/p. This lesson goes one level deeper: tracing exactly which address moves where when you write n1->next = n2;, one step at a time.

n1 is not the box — it points at the box

Node *n1 = new Node(10); creates two things, not one: the Node box itself (wherever new found room for it), and the variable n1, which lives somewhere else entirely and simply holds that box's address.

n1 lives at address 0x600 and holds 0x500. The Node box lives at 0x500 and holds 10 and an empty next. Two boxes, two addresses — exactly Lesson 1's picture, just with a whole Node on the far end instead of a single int.

Quick check — what does the variable n1 itself hold, as a value?

Right — n1's job is to hold the address of the box it points to, not the box's contents, and not its own address.
n1 is a pointer — its value is an address. Specifically, the address of the box it points at (0x500), not its own location or the data inside that box.

Now trace n1->next = n2; as address movements

Three steps, in order:

  1. Look up n1's value → 0x500. That's "go to box1."
  2. Look up n2's value → 0x520. That's the number about to get copied — not n2's own address (0x604), n2's value.
  3. Store 0x520 into box1's next field.

box1's next now holds 0x520 — box2's address. It never touches 0x604 (where the variable n2 itself lives). That number was never relevant to this assignment at all.

Why &n2 would be wrong here: &n2 means "the address of the variable n2," which is 0x604 — the location of a pointer variable, not a Node. Writing 0x604 into box1's next would make box1 "point at" a spot in memory that holds a pointer, not a Node — wrong type, wrong place, and not what you want to traverse into later.

Quick check — using the same addresses (n1@0x600 holds 0x500, n2@0x604 holds 0x520, n3@0x608 holds 0x540), what value ends up in box2's next after n2->next = n3;?

Right — same three steps: go to box2 (n2's value, 0x520), read n3's value (0x540), store that into box2's next.
The value that moves is always the right-hand pointer's value (the address it holds), never its own address.

Second check — one short phrase: n1->next = n2; copies n2's ___, not n2's own address.

Exactly — you copy what n2 holds (its value), never where n2 itself sits.
Re-read step 2 above: what does "look up n2's value" mean, versus &n2?
