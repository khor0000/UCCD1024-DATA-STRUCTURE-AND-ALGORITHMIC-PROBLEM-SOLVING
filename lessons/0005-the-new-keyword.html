Lesson 5 of the linked-list crash sequence · Creating Nodes

The new keyword

new asks the computer, right now, while your program is running, for one fresh chunk of memory big enough to hold whatever you asked for — and hands you back its address. That's the whole definition.

Node *n1 = new Node();   // ask for one fresh Node-sized box, get its address
n1->item = 10;
n1->next = NULL;

cout << n1->item;        // 10

Once you have n1, everything else is the dot-vs-arrow rule from Lesson 3 — n1's type is Node *, a pointer, so it's always ->.

Why not just declare a Node normally?

Here's the real reason new exists, and it's not the one you'd guess. Watch what goes wrong without it:

void attach(Node *ptr) {
    Node tmp;                 // NOT new — an ordinary local variable
    tmp.item = 10;
    ptr->next = &tmp;         // point ptr at tmp's address
}   // the instant this line runs, tmp is destroyed

The moment attach() returns, tmp is gone — but ptr->next is still pointing at the address where tmp used to be. Whatever ptr is part of is now pointing at garbage. This has nothing to do with not knowing how many Nodes you'll need; it happens even if you know for certain you'll only ever need exactly 3.

A hotel room vs. a storage unit. An ordinary variable declared inside a function is like a hotel room booked for one night: the instant checkout time comes (the function returns), housekeeping clears everything out, no matter what you left in there. new is renting a storage unit instead: it keeps existing after you've left the building, and stays there until you specifically go cancel it (free).

A Node has to survive long after the function that created it has returned — it needs to keep existing as part of the list, possibly for the rest of the program. Only new gives you memory with that kind of lifetime.

Rule of thumb: declare normally when something only needs to live as long as the current function/block. Use new when something needs to outlive the function that creates it. Every Node in a list is born inside an insert() call but has to keep existing long after — so it's always new, regardless of whether the final count is known in advance.

Quick check — why does Node tmp; ptr->next = &tmp; break things, even if you're certain the list will only ever hold exactly 3 items?

Right — this is a lifetime problem, not a counting problem. It would break with 1 item or 1000.
Think about what happens to a plain local variable the instant its function returns — regardless of how many items the list ends up holding.
This course's real Node also has two constructors, Node(int) and Node(), which let you write new Node(10) to create-and-fill in one line instead of two. Same box, just a shortcut for filling in item at creation time. You'll see this shortcut everywhere in List.cpp.

Second check — one word: what do you need to write instead of Node tmp; to make it survive past the current function?

Exactly — new is what gives it a lifetime independent of the function that created it.
Look back at the very first code block on this page — what keyword created n1?

One more small piece of vocabulary before you build one: several Nodes chained together (Node 1's next points at Node 2, Node 2's at Node 3, and so on) is called a linked list — that's what you're building by hand next lesson.
