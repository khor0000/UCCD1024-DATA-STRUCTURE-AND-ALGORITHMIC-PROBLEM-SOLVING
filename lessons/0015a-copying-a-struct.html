Lesson 15a of the linked-list crash sequence · the = construct

Copying a struct with =

b = a; where a and b are structs copies every field of a into the matching field of b, one at a time. That is the whole rule, and it is the only new thing in this lesson.

A form with two blanks. A struct is a printed form: book has a blank for the title and a blank for the page count. Copying a form means photocopying it — you get a second sheet with the same words written in the same blanks. Two sheets now exist. Writing on one does not change the other.

The one-number version you already know

int x = 5;
int y = x;      // y is now 5
y = 99;         // x is STILL 5 — two separate boxes

Nothing surprising: y is its own box, and = put a copy of x's value into it.

The struct version

Using the book struct you wrote by hand in lesson 16:

struct book {
    string title;
    int    pages;
};

book a("Dune", 412);
book b = a;                // ← the new construct

That single line does exactly, and only, this:

b.title = a.title;      // "Dune"
b.pages = a.pages;      // 412

Field by field, in declaration order. C++ writes those two lines for you. You did not have to ask for it and there is no way to see it happen — it is silent.

Four boxes at four different addresses. b's two boxes are brand new; the values written inside them were copied from a's. Change b.pages to 500 and a.pages stays 412, for the same reason y = 99 left x alone.

You might reasonably wonder: is book b = a; different from book b; b = a;? For what the paper asks, no — both end with every field of b holding a copy of the matching field of a. Read the two forms as the same thing.

Why this matters more than it looks

Look at that rule once more: every field, copied as-is. Nothing else. Whatever value is sitting in a field gets duplicated, and C++ does not look at what that value means.

For book that is harmless — a title and a page count mean exactly what they say. But you have already met a struct whose field holds an address: List, from lesson 7, whose head field holds the address of the first node. Copy that field as-is and the new List gets the same address — which means it points at the same nodes, not at nodes of its own.

That single consequence is the whole of the next lesson, and the whole of midterm Q3b. You do not need to work it out now. You only need this lesson's rule, cold.

Quick check — book a("Dune", 412); book b = a; b.pages = 500; What is a.pages?

Right. = made b its own pair of boxes and copied the values in. Writing to one pair never touches the other.

On paper • before you move on

Close this page. Write the two lines that C++ silently performs when it runs book b = a;, given struct book { string title; int pages; };

reveal 
b.title = a.title;
b.pages = a.pages;

Two lines, because book has two fields. If book had five fields it would be five lines. The rule scales with the number of fields, and it never reaches past them.
