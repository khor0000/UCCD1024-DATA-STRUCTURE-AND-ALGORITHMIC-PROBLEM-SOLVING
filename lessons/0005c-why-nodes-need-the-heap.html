Lesson 5c of the linked-list crash sequence · Lifetime vs Data Shape

Why Nodes need the heap (and why other variables don't)

Two separate questions often get tangled up into one: "What shape is my data?" vs "How long does my data need to live?" Getting these two separated makes new, struct, and Node instantly click.

The waiter's notepad vs. the restaurant pantry. When a waiter takes your order, they scribble on a notepad. Once the order reaches the kitchen, that scrap of paper is thrown in the trash — it was a temporary calculation. But the ingredients in the pantry must stay in the fridge across all shifts until customers eat them. Local variables are the scrap paper; Nodes in your list are the pantry.

Two completely independent choices

In C++, you choose the shape of your data independently from its lifetime:

On the Stack (temporary, dies at })On the Heap with new (persists until deleted)
Single primitive (e.g. int)int x = 5;
Loop counters, temporary sums		int *p = new int(5); or new int[100];
Dynamic arrays when size is decided at runtime
Bundle (e.g. struct Node)Node a;
Quick temporary struct inside a helper function		Node *n = new Node(10);
Persistent nodes in a linked list / tree

Notice: struct does not mean "heap", and int does not mean "stack". A struct can live on the stack, and an int can live on the heap.

Why can we dispose int x, but must keep a Node?

Think about what each variable is doing in a real program:

void insert(int val) {
    int pos = 1;              // temporary scratchpad — throw away when insert() finishes
    Node *fresh = new Node(val); // persistent data — must survive so find() can read it later!
    // attach fresh into the chain...
}   // pos is destroyed here. fresh (the Node on the heap) survives!
VariableRoleLifetime needed
pos, i, sumTemporary calculation during this single function callOnly while the function runs
Node in a listThe actual data record stored in your collectionLong after insert() finishes, until user removes it

What happens if you write Node a; instead of new?

If you write Node a; inside a function like insert(), a is placed on the stack. The instant insert() finishes, a is wiped out:

void badInsert() {
    Node a;              // lives on the STACK
    a.item = 10;
    head = &a;           // head holds a's address
}   // a is DESTROYED the microsecond this line hits!

// Later in main():
cout << head->item;      // CRASH or GARBAGE — head points to a destroyed box!

Because each Node in a linked list is created inside an insert() call, it must be allocated with new so it stays alive in the heap after insert() returns.

Summary Rule: struct solves grouping data together. new solves keeping memory alive past the function that created it. We use new Node because list items are born inside functions but must survive across the entire program.

Quick check — why does a Node in a linked list need new, while a loop counter int i does not?

Right — loop counters only matter while the loop runs, but a Node holds real data that other functions will need later.
Think about lifetime — when does a function finish, and does the list still need that Node afterwards?

Second check — where does memory created by new live, so it survives after a function ends?

Exactly — the heap. Memory on the heap stays alive until you delete it.
