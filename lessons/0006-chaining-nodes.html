Chaining Nodes by hand

One Node is just a box. A linked list is nothing more than several Nodes where each one's next points at the next box — no List class involved yet. Build one by hand once, and every operation the real List class does will just be "this, but automated."

The word "chain" is used a lot from here on — it means exactly this: the Nodes themselves, linked by next, nothing else. It does not include the List struct you'll meet in lesson 7. The List is a separate little box that stands beside the chain and points into it (via head) — it is not one of the links.
Node *n1 = new Node(10);
Node *n2 = new Node(20);
Node *n3 = new Node(30);

n1->next = n2;   // box 1's note now says "go to box 2"
n2->next = n3;   // box 2's note says "go to box 3"
n3->next = NULL; // box 3 is the last stop

Node *head = n1;  // "head" just remembers where the chain starts

Before the diagram: n1, n2, n3 are three separate pointer variables, and each one lives at its own address, separate from the Node box it points to — the same two-box shape as Lesson 1's x/p. Don't let the short code fool you into thinking n1 "is" the box; it just points at one.

head is a fourth, separate pointer variable — a plain Node * that holds the same address n1 holds (0x500), so you always know where the chain begins. Lose head, and there's no way back to any of these boxes: they're still in memory, but nothing points at them anymore. Keep that thought — it's exactly the bug you'll be hunting for in the lab test.

Walking the chain: traversal

To visit every box in order, start at head and keep following next until you hit NULL:

Node *cur = head;
while (cur != NULL) {
    cout << cur->item << " ";
    cur = cur->next;
}
// prints: 10 20 30

This is the single most important pattern in the whole topic — nearly every List operation is a variation of "start somewhere, follow next, stop at some condition." cur is a temporary pointer you move along the chain; head itself never moves, or you'd lose the start.

Quick check — after the code above, if you ran head = head->next;, what would happen?

Right — this is exactly how "remove the first node" works, and exactly why losing head accidentally is a real bug, not just a style issue.
head is a plain pointer variable — reassigning it just moves where it points. Nothing is deleted automatically, and it doesn't refuse the reassignment.

Second check — in the traversal while loop, what condition on cur stops the loop?

Exactly — cur becomes NULL once you've walked off the last node.
Look at the while condition: while (cur != ___).

If "head doesn't move, cur does" isn't crisp yet, say so now — the rest of the lessons lean on it constantly.
