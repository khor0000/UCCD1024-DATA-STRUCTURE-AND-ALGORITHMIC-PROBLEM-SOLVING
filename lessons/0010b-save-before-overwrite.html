Lesson 10b of the linked-list crash sequence · The one rule behind every ordering trap

Save an address before you overwrite where it lives

You asked whether pre->next = tmp; then tmp->next = cur; — the two relinking lines in the wrong order — breaks the general case.

Direct answer: no. In the general case, those two lines work in either order, as long as cur = pre->next; ran first. That is different from position 1, where swapping the pair really does break it. One rule explains both, and it is the only ordering rule you need to carry into the exam.

One notepad, one address. You are about to paint a wall that has an address written on it. You have one notepad. If you copy the address onto the notepad before you paint, you can still write to the old place afterwards. If you paint first, the address is gone — the notepad never had it. Every pointer line in insert and remove is this: a place that holds an address, and a moment where you paint over it.

The rule. Before a line overwrites a pointer, the address that pointer currently holds must already be saved somewhere else — in another variable, or in another node's next cell. Whatever line does that saving must run first. Nothing else about ordering matters.

Position 1 vs the general case

This is why the two cases feel like different rules but are the same one:

Position 1General case
What holds the address that is about to be overwrittenhead holds the old first nodepre->next holds the node after pre
The line that saves it firsttmp->next = head;cur = pre->next;
The line that overwriteshead = tmp;pre->next = tmp;
Can the last two lines be swapped?No — the save and the overwrite are those two linesYes — the save is a separate earlier line

At position 1, tmp->next = head; is doing double duty: it is both "link the new node" and "save the old first node's address." Swap it after head = tmp; and the save reads head's new value — too late. In the general case the save is its own line, cur = pre->next;, and once it has run the other two lines are free.

Critical Exam Trap • The Save Line Runs First

In any pointer relink, find the line that copies the soon-to-be-overwritten address into a safe place. That line goes first. Everything after it can be written in the order that reads most naturally.

Correct (earns marks)Incorrect (loses marks)
cur = pre->next; before pre->next = tmp;
tmp->next = head; before head = tmp;		 overwriting head or pre->next while it still holds the only copy of an address you need

Quick check — in the position-1 pair, why can't tmp->next = head; run second?

Right — tmp->next = head is the only thing saving the old first node's address, and head = tmp destroys that address. Save before overwrite.
Look at the table: at position 1 the save and the overwrite are those exact two lines. Which one must be saved before the other runs?

Second check — type the one line in the general case that must run before pre->next is overwritten.

Exactly — cur = pre->next; is the save. After it, tmp->next = cur; and pre->next = tmp; are free to run in either order.
It is the line that copies the address of the node after pre into its own variable.
Produce it • closed book

On paper: write the three general-case lines (cur = …, tmp->next = …, pre->next = …) in an order that works. Then, in one sentence, say why cur = pre->next; cannot be the last of the three.

reveal answer 
cur = pre->next;
tmp->next = cur;
pre->next = tmp;

cur = pre->next; is the save. If it runs last, pre->next has already been overwritten to tmp, so cur would capture tmp's address instead of the node that should follow the new one.
