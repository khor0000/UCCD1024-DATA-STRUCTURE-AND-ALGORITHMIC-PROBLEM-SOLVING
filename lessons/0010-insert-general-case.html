insert: the general case

Last lesson handled the two special cases: empty list, and inserting at position 1. Everything else — inserting in the middle, or at the very end — falls through to one shared piece of code. It only ever needs two pointers standing on either side of the gap where the new node goes.

// normal case
pre = find(at-1);   // the node that will come BEFORE the new one
cur = pre->next;    // the node that currently comes after pre

tmp->next = cur;    // new node points forward to cur
pre->next = tmp;    // pre now points forward to the new node

count++;
return true;

Splicing a new link into a chain. To add a new link between two existing links, you don't touch the whole chain — you only need to hold the link right before the gap (pre) and the link right after it (cur). Clip the new link's other end onto cur, then clip pre's open end onto the new link.

at-1 is the key trick: to insert at position 2, you go find the node at position 1 — the one that will sit right before the gap — and call it pre. That single line is why nearly all of insert/remove's "which position do I find()?" confusion goes away once you internalize "find one before where I'm working."

Critical Exam Trap • Save cur Before You Relink

The line cur = pre->next; must come before you overwrite pre->next. Once pre->next = tmp; runs, pre->next holds tmp, so reading it back gives tmp, not the old node — the classic mistake is skipping cur entirely and writing tmp->next = pre->next; after the overwrite, which makes the new node point at itself.

Correct (earns marks)Incorrect (loses marks)
cur = pre->next;
tmp->next = cur;
pre->next = tmp;		 pre->next = tmp;
tmp->next = pre->next; // = tmp

Lesson 10b shows exactly why — and why, once cur is saved, the last two lines can even run in either order.

Right — pre is the node that will sit just before the new one, which is one position earlier than where the new node goes.
pre needs to be the node immediately before the gap. If the new node goes at position at, the node before it is at position at - 1.

Second check — one word: after both relinking lines run, tmp->next holds the same address as which pointer variable?

Right — cur. tmp->next = cur was line 1 of the relink, and nothing changed cur after that. (pre->next now holds tmp, not cur.)
Line 1 of the relink was tmp->next = cur. Did anything change cur or tmp->next after that? pre->next did change — to tmp.
