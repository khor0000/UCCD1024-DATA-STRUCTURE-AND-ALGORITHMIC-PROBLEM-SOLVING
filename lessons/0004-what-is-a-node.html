What is a Node?

A Node is a small box that holds exactly two things: one piece of data, and the address of the next box in the chain. That's the whole definition — everything below is just unpacking what that means.

A treasure hunt. At stop 1 you find a box: inside is a clue and a note reading "next, go to stop 2." At stop 2: another clue, another note pointing to stop 3. Nobody wrote down the whole map in one place — each box only needs to know the very next stop.

This course's exact Node (from Lecture 4):

struct Node {
    int   item;   // the data — the clue in the box
    Node *next;   // the address of the next box (or NULL, if this is the last one)
};

item is the data. next is a pointer — an address — that points at the next Node in the chain. Read Node *next out loud as: "next is a pointer to a Node."

Each box's item is the data (10, 20, 30). Each box's next is a dot standing in for "the address of the next box" — except the last one, whose next is NULL: a special "there is nothing after this" address. NULL is how a Node says "I'm the last stop." Nothing stops you chaining the same shape as many times as you want, box after box, which is exactly how a list of any length gets built from one repeated shape.

Quick check — in struct Node { int item; Node *next; };, what does the next field actually store?

Right — next is a pointer, so it holds an address, never a copy of the whole next box.
next's declared type is Node * — a pointer holds an address, not a copy of the data at that address.

Second check — what value does the last Node in a chain store in its next field?

Exactly — NULL is the "nothing after this" address.

One thing worth double-checking

You might reasonably wonder: how can Node contain a pointer to another Node, when Node isn't even finished being defined yet? It can't contain another Node directly — that really would be a problem. The reason it works is that next only ever stores an address, not a whole Node, and an address is always the same small, fixed size no matter what it points to — same idea as Lesson 1's pointer, just pointing at a whole struct instead of a single int.

struct Node {
    int   item;
    Node  next;    // won't compile — this needs to physically fit a whole Node inside a Node, forever
};

struct Node {
    int   item;
    Node *next;    // fine — this is just an address, always the same small size
};

Quick check — why does Node *next; compile fine, but Node next; (no star) would not?

Right. The star is what turns "contains the actual thing" (impossible, infinite) into "contains the address of the thing" (trivial, fixed size).
Without the star, Node next; is asking to store a whole Node inside a Node — and that inner Node would need to store another whole Node inside itself, forever.
